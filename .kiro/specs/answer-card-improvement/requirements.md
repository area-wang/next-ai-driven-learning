# 答题卡体验优化 - 需求文档

## 介绍

当前的答题界面采用右侧抽屉 + 逐题答题的方式，存在以下用户体验问题：
1. **题目和答题区域分离** - 左侧显示题目，右侧答题，需要频繁切换视线
2. **无法快速浏览** - 无法一眼看到所有题目的答题状态
3. **导航不便** - 无法快速跳转到特定题目
4. **缺少答题卡** - 没有传统考试系统的答题卡概览

## 术语表

- **答题卡（Answer Card）**: 显示所有题目编号和答题状态的概览面板
- **题目区域（Question Area）**: 显示题目内容的主要区域
- **答题区域（Answer Area）**: 用户输入答案的区域
- **富文本答题（Rich Text Answer）**: 使用富文本编辑器作为答题输入方式

## 需求

### 需求 1：答题卡概览面板

**用户故事：** 作为学生，我想要看到所有题目的答题状态概览，以便快速了解答题进度和跳转到特定题目。

#### 验收标准

1. WHEN 用户进入答题模式 THEN 系统应显示答题卡面板，包含所有题目编号
2. WHEN 题目已作答 THEN 答题卡中对应的题号应显示为"已答"状态（绿色标记）
3. WHEN 题目未作答 THEN 答题卡中对应的题号应显示为"未答"状态（灰色）
4. WHEN 用户点击答题卡中的题号 THEN 系统应滚动到对应题目位置
5. WHEN 用户提交答案后 THEN 答题卡应显示正确/错误状态（绿色/红色）

### 需求 2：题目和答题区域一体化

**用户故事：** 作为学生，我想要在同一个视野内看到题目和答题区域，以便减少视线切换，提高答题效率。

#### 验收标准

1. WHEN 用户查看题目 THEN 题目内容和答题区域应在同一个可滚动区域内
2. WHEN 题目包含代码块 THEN 代码块应保持格式化显示
3. WHEN 题目较长 THEN 用户应能够自然滚动查看完整内容
4. WHEN 用户答题 THEN 答题区域应紧跟在题目内容下方

### 需求 3：富文本答题支持（可选）

**用户故事：** 作为学生，我想要使用富文本编辑器回答主观题，以便更好地组织答案结构和插入代码示例。

#### 验收标准

1. WHEN 题目类型为简答题或编程题 THEN 系统应提供富文本编辑器选项
2. WHEN 用户在富文本编辑器中输入 THEN 系统应支持基本格式化（粗体、斜体、代码块）
3. WHEN 用户插入代码块 THEN 系统应提供语法高亮
4. WHEN 用户提交答案 THEN 系统应保存富文本格式

### 需求 4：答题进度实时保存

**用户故事：** 作为学生，我想要答题进度自动保存，以便意外关闭页面后能够恢复答题状态。

#### 验收标准

1. WHEN 用户输入答案 THEN 系统应在 2 秒后自动保存到本地存储
2. WHEN 用户重新打开答题界面 THEN 系统应恢复之前的答题状态
3. WHEN 用户提交答案 THEN 系统应清除本地存储的临时数据
4. WHEN 用户退出答题 THEN 系统应提示是否保存当前进度

### 需求 5：答题模式切换

**用户故事：** 作为学生，我想要在不同的答题模式之间切换，以便根据个人习惯选择最舒适的答题方式。

#### 验收标准

1. WHEN 用户进入答题界面 THEN 系统应提供"卡片模式"和"列表模式"选项
2. WHEN 用户选择"卡片模式" THEN 每道题目应显示为独立卡片，一次只显示一题
3. WHEN 用户选择"列表模式" THEN 所有题目应在一个可滚动列表中显示
4. WHEN 用户切换模式 THEN 系统应保持当前答题状态不变

### 需求 6：答题时间统计

**用户故事：** 作为学生，我想要看到答题用时统计，以便了解自己的答题速度和时间管理。

#### 验收标准

1. WHEN 用户开始答题 THEN 系统应开始计时
2. WHEN 用户查看答题界面 THEN 系统应显示已用时间
3. WHEN 用户提交答案 THEN 系统应记录总用时
4. WHEN 用户查看结果 THEN 系统应显示每道题的答题用时（可选）

### 需求 7：键盘快捷键支持

**用户故事：** 作为学生，我想要使用键盘快捷键导航，以便更快速地在题目之间切换。

#### 验收标准

1. WHEN 用户按下 `N` 键 THEN 系统应跳转到下一题
2. WHEN 用户按下 `P` 键 THEN 系统应跳转到上一题
3. WHEN 用户按下 `S` 键 THEN 系统应保存当前答案
4. WHEN 用户按下 `Ctrl/Cmd + Enter` THEN 系统应提交所有答案
5. WHEN 用户按下 `ESC` 键 THEN 系统应退出答题模式

## 优先级建议

### 高优先级（MVP）
- 需求 1：答题卡概览面板
- 需求 2：题目和答题区域一体化
- 需求 4：答题进度实时保存

### 中优先级
- 需求 5：答题模式切换
- 需求 6：答题时间统计

### 低优先级（增强功能）
- 需求 3：富文本答题支持
- 需求 7：键盘快捷键支持

## 技术考虑

### 富文本编辑器 vs 普通输入框

**富文本编辑器的优势：**
- ✅ 支持格式化（粗体、斜体、列表）
- ✅ 支持代码块和语法高亮
- ✅ 更好的编辑体验
- ✅ 可以插入图片、链接

**富文本编辑器的劣势：**
- ❌ 增加复杂度
- ❌ 可能影响性能
- ❌ 需要额外的存储空间
- ❌ 对于简单题目过于复杂

**建议：**
- 选择题、填空题：使用普通输入框
- 简答题：提供富文本编辑器选项（可切换）
- 编程题：使用代码编辑器（Monaco Editor 或简化版）

### 状态管理

建议使用以下状态结构：
```typescript
interface AnswerCardState {
  mode: 'card' | 'list' // 答题模式
  currentQuestionIndex: number // 当前题目索引
  answers: Record<number, Answer> // 答案记录
  startTime: number // 开始时间
  questionTimes: Record<number, number> // 每题用时
  autoSaveEnabled: boolean // 是否启用自动保存
}

interface Answer {
  value: string // 答案内容
  isRichText: boolean // 是否为富文本
  savedAt: number // 保存时间
}
```
